# 角色模型导入

从系统“文件”选择自己的模型，单文件最多 1 GB（1024 MB）。模型保存在应用私人目录，导入不需要网络或 API。
尺寸自动归一为默认 35 cm，并以脚底为基准放到点击平面。“更多”可调大小与朝向。
删除/重装应用通常会删除应用内模型副本；请保留原始文件。

| 格式 | 当前支持 | 限制 |
| --- | --- | --- |
| USDZ | 系统加载器、贴图、自带命名动画 | 须为自包含包；具体材质效果仍需真机验证 |
| DAE | 网格、命名动画 | 单文件不能依赖外部贴图；完整贴图推荐 USDZ/GLB |
| OBJ | 基础几何 | 不加载独立 MTL/纹理，没有骨骼动画 |
| GLB、VRM | 嵌入 PNG/JPEG、基础材质、动态皮肤绑定；VRM0/1 标准人形骨骼可做程序化动作 | 不导入 glTF 原生动画片段、表情、弹簧物理；不还原 MToon；不支持外部 URI、稀疏访问器、Draco/meshopt |
| BLEND、FBX、PMX、GLTF、SCN | 暂不直接导入 | 需要先用合适工具导出受支持交换格式 |

Blender 或其他建模软件可导出自包含 GLB / USDZ；具体导出能力取决于软件版本和插件。
“有骨骼”不等于“有动作片段”，也不一定有标准人形映射。应用根据模型实际能力显示动作。
VRM0/1 humanBones 用于通用招呼、左右手招手、欢迎、点头、鞠躬、舞动与迈步，不针对某个角色硬编码。
VRM0 的 -Z 前向与 VRM1 的 +Z 前向在渲染时统一为 +Z，网格和骨骼一起转换，不覆盖原文件；参见 [VRM 官方规范](https://vrm.dev/en/vrm/vrm_features/)。
普通 GLB 的皮肤可显示，但任意命名的骨骼不保证被识别人形动作；需要通用人形动作时优先导出带标准映射的 VRM。
从 0.2.3 起，System.Numerics 行向量矩阵显式转换为 SceneKit 原生列向量矩阵，避免平移被写入透视项而拉长网格。
蒙皮使用共同模型根作为绑定空间，保留原骨骼层级和绑定矩阵；iOS UIImage 贴图直接使用原始 UV，不执行额外 V 翻转。
矩阵布局依据 [官方 .NET SceneKit 实现](https://github.com/dotnet/macios/blob/main/src/SceneKit/SCNMatrix4_dotnet.cs)；
UV 行为对照 [glTF 规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#images)及 [SceneKit glTF 加载器](https://github.com/magicien/GLTFSceneKit/blob/master/Sources/GLTFSceneKit/GLTFUnarchiver.swift)。
这是程序化动作，不是动作捕捉、复杂动作生成或完整 IK，效果取决于骨骼布局和权重。请用你自己准备的模型测试。

## 材质诊断与无损副本修正

从 0.2.4 起，GLB / VRM 同时支持基础颜色和发光颜色 / 发光贴图；发光贴图也计入原画质内存保护。
基础颜色乘数不再同时染色发光通道。通用支持不等于完整 MToon 或第三方自定义着色器还原。
应用遵守模型的 `alphaMode`：没有写时按 glTF 默认 `OPAQUE` 处理，不因为 PNG 有透明像素就自动把全部材质改成透明。
参见 [glTF 材质规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#materials)。

若确认模型错误地把阴影遮罩接到了 `baseColorTexture`，或透明眼睛 / 高光层漏写了 `BLEND`，
应只修改对应材质字段并另存副本，不改几何、骨骼、UV 或图片像素。仓库提供 `scripts/repair-vrm-materials.py`，
必须指定经过检查的本地修正计划；工具不会自动猜测材质，默认拒绝覆盖文件，并验证原文件和二进制块不变。
私有修正计划和模型放在被 Git 忽略的 `private-models/` 中，不发布到公开仓库。

## 文件限制与内存保护

文件上限与渲染能力不同。GLB/VRM 按需读取引用数据，不一次性载入 1 GB；从 0.2.2 起保留 200 万顶点、400 万三角形、4096 节点等格式安全边界。
大网格在分配顶点、索引、蒙皮数组之前估算托管数组、SceneKit CPU/GPU、副本转换与骨骼矩阵开销；
构建时按部件分步检查和响应取消。原始网格不自动减面。格式上限不是手机能加载或流畅渲染的保证，内存不足仍会拒绝。
从 0.2.2 起，单个蒙皮绑定支持最多 1024 根骨骼，解决复杂角色辅助骨骼超过旧 256 上限被拒绝的问题。
使用原始 UInt16 骨骼索引，不删减辅助骨骼、不降低贴图或简化网格；每顶点仍须至多 4 个有效骨骼影响。
数组类型错误和数量超限会分别给出具体字段、类型或数量及安全上限；其他结构与内存保护仍保留。
从 0.2.1 起，**贴图按原始分辨率解码，不生成缩小预览、不重压缩、不覆盖原文件**。只解码当前场景实际使用的基础颜色贴图，
同一图片被多个材质引用时只解码一次；未使用的缩略图和不支持的附属材质贴图不上传 GPU。

PNG/JPEG 单图编码最多 64 MiB、编码合计最多 512 MiB，最多 64 张；原始最长边最多 8192、单图最多 64 Mi 像素。
磁盘 GLB/VRM 先读图像头与几何，再逐张按需读贴图，避免把全部编码图片同时留在内存。
上述尺寸只是格式安全边界，不承诺所有 8K / 4K 组合都能加载。

移除了旧的 64 Mi 原始总像素阈值与 1024 缩图逻辑。现在按实际使用的图片估算 CPU 解码、GPU 与 mipmap、
单图临时解码开销，并读取 [Apple 的应用可用内存接口](https://developer.apple.com/documentation/os/os_proc_available_memory)，
至少保留 256 MiB 或当前余量的四分之一（取较大值），在各步骤重查。余量不足时显示预计需求与保护后余量，保留原角色并拒绝新模型；不会自动降画质。
若系统发出内存警告，会取消导入、暂停 AI 并卸载已导入的大模型，以保留应用响应；磁盘原文件不改动。
内存接口是建议值、系统限制可能随时变化；这些措施降低风险，但不保证任意模型都不会被系统终止。
导入时有逐张进度，切到后台会取消。本版没有完整还原 MToon、表情、弹簧物理；“不降画质”指不缩小/重压缩贴图，不代表所有着色器与建模软件完全一致。
原生 USDZ/DAE/OBJ 的加载依赖系统加载器，巨大文件仍可能内存不足；建议优化网格、贴图并保留原始文件。
调整角色尺寸或动作不会覆盖源模型。第三方许可由你确认，公开包不包含这些角色。
